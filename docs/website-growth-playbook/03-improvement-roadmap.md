# 03 · 改进路线图（P0–P3）

> 按依赖与影响力排序，不按日历估时。每一阶段都有「可验收结果」。

---

## 总览

```mermaid
flowchart LR
  P0[P0 止血与转化闭环] --> P1[P1 信任证据升级]
  P1 --> P2[P2 内容阵地与深度页]
  P2 --> P3[P3 增长飞轮与实验]
```

| 阶段 | 目标 | 主要产出 | 依赖 |
|---|---|---|---|
| P0 | 能收到线索、不露馅 | 真表单、CTA、SEO 基础、埋点、Insights 处理 | 对外邮箱或 Webhook |
| P1 | 看得懂且愿意信 | 案例增强、团队照片、信任区、联系完整化 | 业务素材 |
| P2 | 成为内容与销售阵地 | 洞察文章、行业深页、资料下载、JD | 内容生产机制 |
| P3 | 持续获客优化 | 实验、个性化入口、自动化培育 | 有流量与数据 |

---

## P0 · 止血与转化闭环（必须先做）

### 目标
访客点「预约诊断」后，公司侧能收到可用线索；站点在搜索/分享时不「裸奔」。

### 工作包
1. **联系表单后端**（邮件 / 飞书 Webhook / Resend / Formspree 等任选）
2. **全站转化 CTA 补齐**（About/Solutions/Industries/Cases/Careers 尾区）
3. **Insights 导航策略**：隐藏或改为 Coming Soon 落地（禁止假文章卡片充数）
4. **SEO 基础**：`metadataBase`、canonical、hreflang、OG、`sitemap.ts`、`robots.ts`
5. **html lang 随 locale**
6. **基础分析**：PV、CTA 点击、表单提交成功/失败
7. **Reveal 无障碍修复**：`prefers-reduced-motion` + 无 JS 时可见
8. **隐私一句**：表单旁「我们仅用于沟通回复」

### 验收
见 `07-acceptance-criteria.md` → P0。

### 工单
`08-engineer-llm-tickets.md` → TICKET-P0-*

---

## P1 · 信任证据升级

### 目标
客户/投资人离开时能记住「他们真的做过，而且方式不一样」。

### 工作包
1. **案例增强模板**落地到 3 个现有案例（指标、周期、适用对象、CTA）
2. **团队照片与履历校对**（花名策略保持）
3. **首页社会证明条**（行业类型/项目类型，不编造 Logo）
4. **企业信任区**（协作方式、里程碑门禁、数据原则）— About 或 Solutions
5. **联系页完整化**（邮箱必有；微信/电话可选；响应时效）
6. **诊断服务说明抽屉/锚点**（什么是诊断、产出物）
7. **英文文案去直译**（messaging kit）

### 验收
P1 清单；至少 1 个案例有清晰量化 + 页内 CTA。

---

## P2 · 内容阵地与深度页

### 目标
官网开始「自己带来询盘」，而不仅是「被发送链接后浏览」。

### 工作包
1. Insights 真实上线（首批 3 篇：方法论 / 制造 / 项目复盘脱敏）
2. 行业页升级为着陆页（制造、政企优先）
3. 解决方案「商品化」：交付物样例、周期区间、适合/不适合
4. Careers JD 完整化 + 投递字段
5. 可下载一页纸 / 公司介绍（PDF）
6. Organization JSON-LD + JobPosting（有 JD 后）
7. 图片逐步替换为真实现场/团队（有素材再换）

---

## P3 · 增长飞轮与实验

### 目标
用数据驱动迭代，形成内容与转化的复利。

### 工作包
1. 按意图的落地参数（`?intent=` 已有，扩展 UTM）
2. Hero CTA / 案例排序 AB（简单即可）
3. 询盘自动分类与飞书多维表
4. 内容日历与个人 IP → 公司 Insights 分发
5. 多语言细节打磨（英文独立润色，而非同步直译）
6. 性能与 Core Web Vitals 精修
7. 自定义域名品牌化、邮箱域名一致性

---

## 明确不做（本阶段）

- 拆成客户版/投资人版两套官网
- 展示融资金额/估值
- 公开内部主线/支线资源分配口径
- 政企合作路径细节
- 堆砌 AI 视觉陈词滥调
- 为了「丰富」而虚构客户 Logo 与数据
